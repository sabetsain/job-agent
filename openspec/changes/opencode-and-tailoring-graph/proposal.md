## Why

The foundational deterministic ingestion, pre-filtering, and SQLite state store (`schemas-and-ingestion`) are complete, leaving passing postings sitting in `Pending_Scoring`. To deliver the core job-hunting co-pilot experience defined in `docs/INTENT.md`, we now need the LLM-powered evaluation, drafting, auditing, Typst PDF compilation, and conversational human-in-the-loop (HITL) ideation engine — built locally first with a CLI review harness and a dedicated evals suite so the full workflow is verified before wiring up Slack and GCP.

## What Changes

- **OpenCode Go Dual-Tier Model Client & Dedicated System Prompts:**
  - Add a git-tracked `config/llm.yaml` (and `config/llm.example.yaml`) configuring the OpenCode Go OpenAI-compatible base URL (`https://opencode.ai/zen/go/v1`), API key env var (`OPENCODE_API_KEY`), and **dual-tier model routing**: a **free model** (`scoring_model`) for Stage 1 fit scoring & thread intent classification (`CHAT` vs. `REITERATE`), and a **cheap paid reasoning model** (`reasoning_model`, with optional `reasoning_effort`) for planning, writing, auditing, and ideation. Optional per-tier `base_url` / `api_key_env` overrides allow mixing endpoints cleanly while defaulting to the shared OpenCode Go config.
  - Enforce structured outputs via LangChain/LangGraph native `with_structured_output(PydanticModel)` across every **LLM** agent node — including Stage 1 fit scoring (explicitly excluding the deterministic Typst `Compiler`) — behind an injectable client protocol with bounded parse-repair retries for offline unit testing.
  - Give **every** LLM agent/node (`scorer`, `planner`, `writer`, `auditor`, `ideation`, `intent_router`) its own dedicated, version-controlled system prompt file under `src/job_agent/prompts/` loaded automatically at startup (fail-fast, cached in memory) — embedding `application-voice` (Writer), `blader/humanizer` (Auditor), diverse transferable-skill examples, and clear senior+/non-technical tell-tales.
  - **BREAKING** *(config schema)*: Remove `voice_skill_path` from `JobPreferences` in favor of dedicated system prompt files.
- **Stage 1 Fit Scorer, Tiered Fit Thresholds & SQLite Draft Queue:**
  - Evaluate **all** `Pending_Scoring` postings (no 3-job cap on scoring): `scoring_model` returns LangChain-enforced structured evidence (`ScoringEvidence`, including `is_technical`, `inferred_min_years`, seniority signals, direct/transferable/missing skills, 0–10 sub-scores, and major unaddressed gaps) while Python deterministically computes the weighted fit score from `ScoringRubric`, automatically scores out **non-technical** roles (`is_technical == False`) and hidden `senior_plus` roles (primarily via required years of experience > `max_years_experience`), enforces tiered seniority & minimum-fit thresholds (**65%** minimum fit for `entry_level` / junior roles with transferable skill credit `1.0`, **95%** minimum fit for `stretch` / mid-level ~2y roles with transferable skill credit `0.0`), attaches a `missing_posted_at` flag when `posted_at` is `None`, and transitions each row to `Queued_For_Drafting` or `Scored_Out`.
  - **BREAKING** *(config schema)*: Replace the single flat `ScoringRubric.min_fit_score` (`7.5`) with the tiered seniority thresholds (`entry_level`: `0.65` / 65%, `stretch`: `0.95` / 95%) so scoring has one unambiguous threshold model.
  - Drain at most `daily_draft_limit` (`3`, strictly an upper cap, never a quota) from `Queued_For_Drafting` → `Pending_Review`, prioritizing the preferred window (`posted_at <= 7d` or active future `application_deadline`) over older eligible postings (`8–21d`), with **strict FIFO** (`created_at ASC`, tie-breaking by `fit_score DESC`) within each tier.
  - Expire queued non-manual jobs whose `application_deadline` has passed or whose `posted_at` aged past `max_age_days` (`Expired`) before spending drafting tokens, and expose queue depth inspection via CLI.
- **Stage 2 LangGraph Tailoring, Two-Pass Auditing & HITL Ideation:**
  - Implement a persistent per-job LangGraph workflow (`Planner -> Writer -> Deterministic Auditor -> LLM Auditor -> Compiler -> Human Review Interrupt`) backed by SQLite checkpointing (`langgraph_thread_id`), designed for clean migration to Postgres.
  - Clarify **major unaddressed gaps** explicitly (primary mandatory posting requirements with neither direct nor closely transferable coverage in `MasterProfile`; excluding noisy minor tools/nice-to-haves).
  - Split auditing into two passes, both returning structured `AuditViolation` diagnostics (`document`, `location`, `rule`, `offending_snippet`, `fix_instruction`) so the Writer performs surgical fixes with minimal guesswork: (1) a zero-token **Deterministic Python Gate** (verified with `mutmut` and full multi-paragraph EN/DA + "obviously AI" fixtures) and (2) an **LLM Auditor** (`reasoning_model` with `blader/humanizer` rules).
  - Cap internal self-correction loops (Writer ↔ Auditor / Compiler) to **at most 2 passes** per generation cycle. When the second internal pass completes, the draft **must always be sent to the Compiler** to compile PDFs and surface any remaining warnings to the human. The outer **human ideation ↔ re-iteration** loop is unbounded.
  - Emit an explicit user-visible progress message (e.g., `"Workshopping now..."`) whenever drafting or re-iteration starts so the human always knows work is actively underway before pausing at the Human Review interrupt.
  - Support open back-and-forth ideation in the thread without forcing PDF regeneration on every reply; `scoring_model` (free model) classifies thread replies to route explicit rewrite requests (e.g., *"retry, swapping education and work experience"*) straight through `ideation -> re-iterate -> Planner` in a single turn, while `approve` and `dismiss` remain explicit actions (CLI commands now; Slack Block Kit buttons later).
  - Instruct `prompts/ideation.md` to actively detect user-stated facts that **add to or drift from/contradict** `MasterProfile` — treating the **human as the final source of truth** at all times — recording them in thread-scoped `session_verified_facts` AND persisting them to the SQLite weekly cache (`profile_update_suggestions`) for the future `weekly-profile-checkin` session without mutating `master_profile.yaml` during the week.
  - Provide a local CLI interactive harness (`job-agent score`, `job-agent draft`, `job-agent review <job_id>`, `job-agent queue`) so the full pipeline is testable end-to-end before Slack integration.
- **Typst Document Rendering & Page-Budget Loop:**
  - Adopt **Typst** via the `typst` Python wheel (updating `openspec/config.yaml` from LaTeX → Typst and `/inference/go/openai` → `https://opencode.ai/zen/go/v1`) using the open-source MIT-licensed `basic-resume` single-column ATS-friendly template for CVs and a **custom** Typst Cover Letter template designed to visually match it, both fed directly from validated `TailoredCV` / `TailoredCoverLetter` Pydantic JSON (zero escaping bugs, native Danish `æ/ø/å`, offline-capable).
  - Lock body typography strictly to **`9pt` floor and `12pt` ceiling** (default `10pt`; body text only, excluding headers, sub-headers, and footers) and preserve margins; verify compiled PDF page counts deterministically and route page overflows back to the Writer to trim prose rather than shrinking fonts.
- **Scoring Evals Suite & Explicit Environment Hygiene:**
  - Add a dedicated evals suite (`tests/evals/`) with a synthetic test `MasterProfile` and curated test job listings covering entry-level direct matches, entry-level transferable matches (≥65%), entry-level misses (<65%), mid-level/stretch transferable-only rejects (0.0 credit, <95%), mid-level/stretch direct matches (≥95%), hidden senior+ rejects, non-technical rejects, Danish postings, and missing `posted_at` flags — runnable both deterministically offline and live against OpenCode Go.
  - Add `.python-version`, `.env.example`, and `.antigravityignore` (shielding `.env*` and local secrets/DBs from AI tooling alongside `.gitignore`) so the environment and secrets boundaries are explicit and deployment-ready.

## Capabilities

### New Capabilities
- `llm-provider-and-prompts`: OpenCode Go dual-tier model configuration (`config/llm.yaml`: free `scoring_model` + cheap paid `reasoning_model`), native LangChain/LangGraph structured output client wrapper for all LLM nodes (excluding deterministic Compiler), startup-loaded dedicated version-controlled system prompts for all 6 agent nodes, and `.antigravityignore` / `.env.example` secrets hygiene.
- `fit-scoring-and-draft-queue`: Hybrid free-LLM (LangChain structured output) + deterministic Python fit scorer over all `Pending_Scoring` postings, auto-rejecting non-technical and hidden senior+ roles, tiered 65% junior / 95% mid-level thresholds with Option B transferability and diverse transferable examples, missing-timestamp flagging, pre-draft queue expiration/draining, and a curated scoring evals suite.
- `tailoring-and-hitl-graph`: Stateful LangGraph tailoring and conversational ideation workflow with SQLite checkpointing, explicit definition of major gaps, two-pass deterministic + `blader/humanizer` LLM auditing returning surgical `AuditViolation` locations, bounded max-2 internal passes always compiling for human review, loud `"Workshopping now..."` progress feedback, unbounded human ideation/re-iteration cycles, free-model one-shot `ideation -> re-iterate` routing, human-as-source-of-truth profile drift/addition detection into the weekly SQLite cache, and local CLI review harness.
- `typst-document-rendering`: Bilingual (`da`/`en`) Typst compilation via the `typst` Python wheel using the open-source `basic-resume` CV template and a custom matching Cover Letter template fed directly from validated JSON, enforcing `[9pt, 12pt]` body font bounds and deterministic PDF page-count verification.

### Modified Capabilities
- `domain-schemas`: Add `Queued_For_Drafting`, `Scored_Out`, and `Expired` to `ApplicationStatus`; remove `voice_skill_path` from `JobPreferences`; replace flat `ScoringRubric.min_fit_score` with tiered seniority thresholds (`entry_level` 65% / `stretch` 95%); add body font ceiling (`<= 12.0pt`) to `LayoutGuardrails`; add dual-tier `LLMConfig` schema and YAML loader.
- `local-state-store`: Transition priority candidate draining from `Pending_Scoring` to `Queued_For_Drafting` with FIFO ordering within priority tiers, add pre-draft queue expiration and queue depth queries, add the `profile_update_suggestions` weekly cache table (supporting both additions and corrections/drift), and add CLI commands for scoring, drafting, queue inspection, and local review.
